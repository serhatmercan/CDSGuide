# Appendix — ADT Tips & SAP Transaction Codes

## What is it?

A quick-reference collection of ABAP Development Tools (ADT/Eclipse) navigation shortcuts, project explorer search patterns, and SAP GUI transaction codes useful while working through this guide.

## Comment Syntax Reference

ABAP source and CDS source use **different** comment characters. Mixing them up is one of the most common first-time errors when moving between a report and a DDL source.

**ABAP** (reports, classes, AMDP method bodies):

| Style | Syntax | Notes |
|---|---|---|
| Full-line comment | `* comment` | Asterisk must be in the **first column** |
| Line / end-of-line comment | `" comment` | Comments out the rest of the line |

**CDS DDL and DCL** (`define view`, `define view entity`, `define table function`, `define role`):

| Style | Syntax | Notes |
|---|---|---|
| Line comment | `// comment` | Runs to the end of the line — the recommended form |
| Inline / multi-line comment | `/* comment */` | Can be used within a line or across several lines |

> ⚠️ `"` is **not** a comment character in CDS DDL/DCL, and `//` `/* */` have no meaning in ABAP source. All CDS code samples in this guide use `//`; all ABAP samples use `"`.

## ADT (Eclipse) Project Explorer — Finding Objects

| Goal | How |
|---|---|
| Find your own custom (`Z`/`Y`) CDS views | **Project Explorer** → Search: `*z*` `type:ddls` |
| Find SAP demo CDS views (e.g. `SNWD_*` flight/EPM models used throughout this guide's examples) | **Project Explorer** → Search: `*demo*` `type:ddls` |
| Find standard SAP CDS views for a specific area (e.g. material) | **Project Explorer** → Search: `*material*` `type:ddls` |
| Open any ABAP Development Object directly by name | `Ctrl + Shift + A` (Open ABAP Development Object) |

> 💡 The `type:` filter in ADT's search isn't limited to `ddls` (CDS views) — the same pattern works for other object types, e.g. `type:clas` for classes, `type:intf` for interfaces, `type:tabl` for tables.

## Performance Tracing

| Goal | How |
|---|---|
| Trace the actual SQL generated by a CDS view (joins, associations resolved, etc.) | `ST05` — start an **SQL Trace** (Activate Trace → run your report/app → Deactivate Trace), then analyze the trace list |

`ST05` is the single most useful tool for understanding what a CDS view *actually* does at the database level — especially for confirming whether an association was resolved into a join, or whether a `WHERE`/`HAVING` condition was pushed down as expected. See the performance notes throughout [03-Data-Modeling](../03-Data-Modeling/Association.md) and [07-Query-and-Reporting/Query.md](../07-Query-and-Reporting/Query.md) for where this matters most.

## Useful SAP Transaction Codes (expanded reference)

| T-Code | Purpose |
|---|---|
| `SE11` | ABAP Dictionary — inspect the generated SQL view name/structure for a CDS view. |
| `SE80` / `SE24` | Object Navigator / Class Builder. |
| `ST05` | SQL Trace — analyze CDS view performance and generated SQL. |
| `SEGW` | Gateway Service Builder (classic, manually-modeled OData services). |
| `/IWFND/MAINT_SERVICE` | Activate/register OData services (including those generated via `@OData.publish`, see [08-OData-and-Consumption/OData.md](../08-OData-and-Consumption/OData.md)). |
| `/IWBEP/REG_SERVICE` | Backend service registration (Gateway hub scenarios). |
| `SU01` / `PFCG` | User and role maintenance — used to test [Access Control (DCL)](../09-Security/AccessControl.md) with realistic, restricted test users. |
| `SU21` | Maintain authorization objects (referenced by `aspect pfcg_auth` in DCL roles). |
| `RSRT` | Test/execute analytical queries (`@Analytics.query: true` views). |
| `SLG1` | Application log — useful when exit classes ([10-Examples/Class.md](../10-Examples/Class.md)) log errors/warnings. |
| `SCC4` / `SCC1` | Client maintenance/copy — relevant background for understanding `@ClientHandling` behavior. |
